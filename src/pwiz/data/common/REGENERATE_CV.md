# Regenerating CV Files

This document explains how to regenerate the CV (Controlled Vocabulary) source
files from the OBO (Open Biomedical Ontologies) files.

## Overview

The CV files in mzR are generated from OBO ontology files. The generation process
uses the `cvgen` tool which is part of the Proteowizard library.

**Important:** The Proteowizard project has been restructured to .NET/CLI. The 
C++ source files (cv.hpp, cv.cpp, CVTranslator.*) are no longer available from
their GitHub repository. These files are maintained locally in mzR.

## Files

### OBO Source Files
- `psi-ms.obo` - PSI-MS Mass Spectrometry Ontology (latest version from HUPO-PSI)
- `unimod.obo` - UniMod PTM Modification Ontology (from unimod.org)
- `unit.obo` - Unit Ontology (UO) (from bio-ontology-research-group)

### Generated Files
- `cv.hpp` - C++ header with CV term enum and declarations (generated by cvgen)
- `cv.cpp` - C++ implementation with CV term data (generated by cvgen)

### Local mzR Files (NEVER downloaded from upstream)
- `CVTranslator.hpp` - CV text-to-term translation header
- `CVTranslator.cpp` - CV translation implementation with mzR-specific logic
- `CVTranslatorTest.cpp` - Unit tests for CVTranslator

## Critical Build Constraint: boost::utility::singleton.hpp

**WARNING:** The cvgen tool requires `boost::utility::singleton.hpp`, which was 
**removed from Boost 1.70 and later versions** (around 2020). Modern Boost 
installations (including Homebrew, apt, and Bioconductor Docker images) do 
**NOT** provide this header.

### Why This Matters
- Ubuntu 20.04+ (Boost 1.71+) and later do NOT have singleton.hpp
- The bundled boost in `src/boost/utility/singleton.hpp` provides a workaround
- Bioconductor Docker images have modern Boost and require special handling

### Workarounds

**Option 1: Use the bundled singleton.hpp (recommended)**

The file `src/boost/utility/singleton.hpp` is included in this repository.
Ensure your boost include path prioritizes this file.

**Option 2: Manual singleton.hpp creation**

If your system lacks singleton.hpp, create it at the boost utility path:

```bash
cat > /path/to/boost/utility/singleton.hpp << 'EOF'
// Copyright (c) 2003-2005 David Abrahams
// Copyright (c) 2004 Daniel Weinig
// Distributed under the Boost Software License, Version 1.0.

#ifndef BOOST_SINGLETON_HPP_INCLUDED
#define BOOST_SINGLETON_HPP_INCLUDED

#include <boost/noncopyable.hpp>

namespace boost {

struct restricted {};

namespace detail {
template<typename T>
struct singleton_holder {
    static T& instance() {
        static T obj(restricted());
        return obj;
    }
};
}

template<typename T>
class singleton : private noncopyable {
public:
    static T& instance() {
        return detail::singleton_holder<T>::instance();
    }
};

} // namespace boost

#endif // BOOST_SINGLETON_HPP_INCLUDED
EOF
```

## The Update Process

### Step 1: Download Latest OBO Files
```bash
cd src
./updateCvParams.sh
```

This script downloads the latest .obo files from their upstream repositories.

### Step 2: Verify Version Compatibility

Check if your cv.hpp/cv.cpp are compatible with the downloaded .obo files:

```bash
# Check psi-ms.obo version
grep "data-version:" src/pwiz/data/common/psi-ms.obo

# Check cv.hpp version
grep "data-version:" src/pwiz/data/common/cv.hpp
```

**If versions match:** You're done. The package should compile correctly.

**If versions differ:** You need to regenerate cv.hpp/cv.cpp (see Step 3).

### Step 3: Regenerate cv.hpp and cv.cpp (Advanced)

If you have a working cvgen with the bundled singleton.hpp:

```bash
cd src/pwiz/data/common
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j4 cvgen
./cvgen ../psi-ms.obo ../unimod.obo ../unit.obo
```

**OR** use the bundled boost with the custom include path:

```bash
cd src
g++ -std=c++17 -Isrc -Isrc/pwiz -Isrc/pwiz/data/common \
    -o cvgen_new src/pwiz/data/common/cvgen.cpp \
    src/pwiz/data/common/obo.cpp \
    -lboost_filesystem -lboost_system -lboost_regex \
    -Isrc/boost
```

### Step 4: Update CVTranslator.cpp if needed

After regenerating cv.hpp/cv.cpp with a new OBO version, check for compilation errors
in CVTranslator.cpp related to undefined CVID identifiers. Update the `shouldIgnore()`
and `shouldReplace()` functions to handle any new conflicts.

### Step 5: Verify the Build
```bash
cd /Users/adrutz/Git/mzR
R CMD INSTALL .
Rscript -e "library(mzR); packageVersion('mzR')"
```

## CVTranslator Files - What You Need to Know

The `CVTranslator.cpp` file contains mzR-specific modifications that handle
CV term conflicts. The key function is `shouldIgnore()`:

```cpp
bool shouldIgnore(const string& key, CVID value, CVID cvid)
{
    return (key=="unit_" && value==MS_unit_OBSOLETE && cvid==UO_unit ||
            key=="pi_" && value==MS_PI && cvid==UO_pi || // MS_PI vs UO_pi conflict
            key=="pi_" && value==MS_PI && cvid==MS_pI || // isoelectric point vs photoionization
            key=="de_" && value==MS_DE && cvid==1001274 || // conflict
            cvid == UO_volt_second_per_square_centimeter); // conflict
}
```

These functions handle specific conflicts that arise when the same term name
maps to different CVID values across ontologies. **Do not overwrite these files
from upstream** - they are mzR-local modifications.

## CI/CD Recommendations

For automated CI/CD purposes:

1. **Never attempt to download CVTranslator.* files** - they return 404 from Proteowizard
2. **Only download .obo files** using `updateCvParams.sh`
3. **Keep cv.hpp/cv.cpp at versions that work with your boost installation**
4. **Keep CVTranslator.* files in version control** - do not overwrite

The CI system should:
- Assume cv.hpp, cv.cpp, and CVTranslator.* are already present and correct
- Only update .obo files if CV regeneration infrastructure is available

## Troubleshooting

### "undeclared identifier" errors after compilation

This occurs when cv.cpp references enum values that don't exist in cv.hpp.
This can happen when:
- CV terms have been renamed or removed upstream
- The .obo files are from a different version than the generated files

**Solution:**
1. Check that psi-ms.obo version matches cv.hpp version:
   ```bash
   head -3 src/pwiz/data/common/psi-ms.obo
   grep "data-version:" src/pwiz/data/common/cv.hpp
   ```
2. If versions don't match, regenerate cv.hpp/cv.cpp from matching .obo files,
   or manually edit cv.cpp to match the current cv.hpp.

### CVTranslator.cpp compilation errors

If you see errors in CVTranslator.cpp, check for:
- Missing CV term references (need to add to shouldIgnore/shouldReplace)
- Changed enum names (need to update the code)

The fix is to update the shouldIgnore/shouldReplace functions to handle
the new/removed terms.

## Making Changes

When you need to add new conflict resolution logic:

1. Identify the conflict in CVTranslator.cpp
2. Add the new case to `shouldIgnore()` or `shouldReplace()`
3. Test with the relevant CV terms
4. Commit the changes to CVTranslator.cpp

Do NOT attempt to regenerate CVTranslator.* files - they are mzR-local.
